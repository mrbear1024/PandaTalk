# Building in Public：一个中文独立开发者的尝试

> 在 X 上写英文、在公众号写中文，这一年我学到了什么。

## 为什么要 Building in Public

过去一年，我做了两件看起来「傻」的事：

- 把每周的产品进度，都发到 X 上；
- 把每个月的思考与复盘，都写成公众号文章。

收入没有立刻翻倍，但以下这些东西，悄悄长了出来：

- **合作机会**：不止一个未来可能的合伙人，是从一条推文 / 一篇文章里认识的；
- **反馈密度**：你正在做的东西，每天都有人在告诉你「这里可以更好」；
- **自我纪律**：每周都要输出，会逼你停下来想清楚 —— 这周我到底做了什么？

## 中文 vs 英文：两个平行宇宙

这一年我逐渐意识到：**中文独立开发者圈** 和 **英文独立开发者圈** 是两个平行宇宙。

|  | 中文圈（公众号 / 小红书） | 英文圈（X / IndieHackers） |
| --- | --- | --- |
| 阅读时长 | 长文为主 | 短推 / 线程为主 |
| 互动方式 | 偏「看」 | 偏「聊」 |
| 变现形式 | 课程 / 社群 / 咨询 | SaaS / 订阅 / 付费 API |
| 对 AI 态度 | 好奇 + 焦虑 | 好奇 + 执行 |

**结论**：两边都值得写，但要用两边的语言去写。

## 三条对我最有用的建议

1. **别等完美了再发**。你以为「再打磨一周就发」，其实那一周就是永远；
2. **先写给一个具体的人**。每次动笔前，想象你在对谁说话；
3. **保持长期的节奏**，比偶尔的爆款重要一百倍。
